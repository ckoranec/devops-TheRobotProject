## Customer journey

Menu / Order → Delivery location → sign in or create account → select/confirm route → save and continue to checkout → purchase-specific delivery maps → one Snack Chase attempt → earned coupon wallet → next checkout.

V32 replaces developer-oriented Delivery Location copy and layout with a customer form and map. Coordinates are optional, account sign-in is visible to guests, account creation also signs in, saved destinations lead to checkout. Coupon Wallet now has guest sign-in, empty and earned-coupon states instead of a raw authentication error. Existing main navigation receives Delivery location and My coupons links. Core three-map geometry/sizing files are untouched by V32.

V31 is included and installed only if missing. It implements one attempt and at most one earned coupon per confirmed purchase, no daily limit, server prices, expiration and one-use redemption in explicit local demo checkout. Production payment confirmation is not connected; production defaults deny checkout completion. No money is charged or robot dispatched in demo checkout.

## Release gates

1. Local tests and browser acceptance on 127.0.0.1:8000.
2. Exact source review generated by prepare_release.py. No backups, databases, secrets or unrelated IDE files staged.
3. Explicit review approval, then publish_reviewed_release.py verifies unchanged reviewed content and pushes DevOps without force.
4. Read-only server_release_check.py identifies Nginx API routing, existing services, listener addresses and account database paths without reading secrets or database contents.
5. Prepare the backend-capable deployment against that actual server configuration. Preserve account data and private secrets; use a production WSGI service, not the development server.
6. Verify the exact approved commit through live static assets and owner-scoped API checks. Keep payment and real GPS disabled/unclaimed until integrated.

Never state ALL MAP ITEMS ARE COMPLETE until zero packages remain and their acceptance evidence is recorded.
